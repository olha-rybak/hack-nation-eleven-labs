# T-300 · Guardrail engine — catching it before the save
**Lane B · depends on: T-200, T-103**

Evaluate live events against a confirmed Work Map's guardrails and fire *before* a destructive action
commits. The `GuardrailCheck` on each guardrail is the machine-evaluable form the LLM derived from the
expert's words during the debrief:

```python
GuardrailCheck(trigger_kind, entity_pattern, field,
               condition: str,     # "amount > 5000 and after == '4711'"
               severity: Literal["warn","stop"])
```

Two timing requirements, and they are the whole ticket:

- Evaluate on the **edit** event, not the save — the tutor must speak before the new hire clicks Save.
- When severity is `stop`, the tutor interrupts immediately, bypassing the pause detector's cooldown.
  Politeness rules are for questions; a guardrail about to be broken outranks them.

Conditions are generated by an LLM but evaluated in a restricted expression evaluator, not `eval`.

**Acceptance:** a scripted event stream that codes a €7,200 equipment invoice to 4711 fires a `stop` on
the edit event, with the governing guardrail and its quote attached, before any save event exists.
